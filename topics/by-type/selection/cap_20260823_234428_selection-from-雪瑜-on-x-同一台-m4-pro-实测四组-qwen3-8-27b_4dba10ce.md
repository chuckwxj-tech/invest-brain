# Selection from: 雪瑜 on X: "同一台 M4 Pro 实测四组 Qwen3.8-27B：DFlash2、MTP 到底怎么选" / X

## 用户备注

_无备注_

## 原文

前面我已经在本地装好了 Qwen3.8-27B 官方 4-bit、DFlash2 和 Uncensored 版本，最近又补上了 oQ4e + MTP。现在同一台 48GB M4 Pro 上一共有四组可运行配置，也终于可以把普通解码、外置草稿模型和模型原生 MTP 放在一起看。
先说最重要的结果。在原来三组同口径短提示测试里，官方 4-bit 和 Uncensored 4-bit 都是约 15.4 token/s；官方 4-bit 加 DFlash2 后平均达到 26.96 token/s，提升 75%。新加入的 oQ4e + MTP 在另一套更长、更接近 Agent 工作负载的测试中，长文平均 24.9 token/s，代码平均 34.1 token/s。
这两套数字不能直接排成一个绝对榜单，因为提示词长度、生成长度、采样方式和推理引擎都不同。但它们已经足够回答实际选择问题：DFlash2 是现有官方 4-bit 上最直接的加速方案；MTP 的代码吞吐更高，还能配合 oMLX 的 ANE prefill 和 262K 上下文，不过部署复杂度与首 token 等待也明显更高。

这里仍然要区分“模型”和“运行配置”。DFlash2 不是单独聊天的大模型，而是约 3.6GB 的草稿模型，最终输出仍由官方 27B 主模型验证。oQ4e + MTP 则是另一份 Qwen3.8-27B 量化权重，主体采用 4-bit affine g64，并给部分敏感张量保留 5-bit，同时包含原生 MTP head。
02｜前三组严格横测：DFlash2 平均快了 75%
前三组继续沿用原来的统一口径：64-token 简短解释、128-token 数学推理、128-token Python 代码生成。每组先预热一次，再使用相同采样参数计时，DFlash2 使用 block-size 4。
DFlash2 相比官方普通解码平均提升 1.75 倍，同时多占约 3.96GB 峰值内存。加载时间只增加约 0.46 秒，首 token 没有变慢。
Uncensored 版本比官方版快约 0.22%，属于正常测试波动。它改变的是安全对齐与拒答行为，不是用来换取吞吐的性能版本。
03｜DFlash2 的收益取决于任务
拆开三类提示词，DFlash2 并不是固定翻倍：
数学推理达到 35.37 token/s，是普通解码的 2.30 倍；短回答和代码生成则是约 1.47～1.48 倍。差异来自草稿接受率：数学推理每轮验证平均接受 3.63 个 token，短解释和代码只有 2.33、2.35。
DFlash2 的收益会随提示词、输出结构、采样参数和块大小变化。
04｜第四组：oQ4e + MTP 的代码吞吐更突出
MTP 这组使用 oMLX 0.6.3rc2，开启原生 MTP k=3、双 ANE prefill，并保留 262144 context 配置。实测负载是约 2.1K～2.4K token 输入、生成约 320 token，长文与代码各跑 3 次并预热。
代码比长文快很多，符合 MTP 的工作方式：输出结构越可预测，草稿 token 的接受率越高，一轮验证能向前推进得越多。上游测试中代码接受率接近 99.6%，长文约为 75%～80%，本机结果也呈现出相同趋势。
MTP 的代价主要在部署和 prefill。ANE 原始单银行在本机 macOS 15 上加载失败，最后由 oMLX 自动拆分后才成功；48GB 机器的 Metal 默认上限也会让部分 prefill chunk 从 2048 降到 576 或 1024。因此这轮长输入测试的首 token 需要 14～21 秒，不能和前三组不到 1 秒的短提示 TTFT 直接比较。
反过来看，MTP 也不是简单的“DFlash2 更快版”。它使用不同量化权重、不同推理栈和原生预测头，优势集中在长输出与代码生成；DFlash2 则可以继续复用现有官方 4-bit 主模型，配置更直观，短提示首 token 也更轻快。
05｜GSM8K：DFlash2 达到 31.49 token/s
原三组配置还跑了 GSM8K 测试集开头固定的 5 道题，使用贪心解码，每题最多生成 256 token。MTP 尚未用同一脚本补跑，因此这里不把它塞进质量对比表。
DFlash2 在这部分达到普通解码的 2.08 倍。三组在前两道、第四道和第五道题上都答对；剩下的房屋翻修题在讨论“价值增加 150%”的歧义时触及 256-token 上限，没来得及输出最终答案。
因此更准确的表述是“5 题中 4 题在 token 上限内完成且答对”，而不是宣称真实正确率只有 80%。这组样本也不足以比较官方版与 Uncensored 版的能力差异。
06｜四组配置应该怎么选
官方 4-bit 仍然是最简单的基准方案。它约占 16GB 磁盘，运行峰值约 15.5GB，速度稳定在 15.4 token/s 左右，依赖最少，排错也容易。
DFlash2 是我当前的日常默认选择。它额外占用约 4GB 峰值内存，但前三组同口径测试平均提升 75%，数学和 GSM8K 场景超过两倍，而且短提示首 token 仍然不到 1 秒。对聊天、推理和通用 Agent 来说，它在速度、响应和部署复杂度之间最均衡。
oQ4e + MTP 更适合代码 Agent 和长输出。在这台 M4 Pro 上，代码平均 34.1 token/s，是四组方案里目前最亮眼的本机代码结果；但长输入 TTFT、独立 oMLX 环境、ANE 内核和启动参数都增加了维护成本。它值得保留为高吞吐代码方案，但还不能用现有数据断言它在所有场景都快于 DFlash2。
Uncensored 版只适合受控的红队与拒答机制研究。它没有性能红利，又移除了大量安全护栏，不应该在缺少权限隔离、内容过滤和人工审核时接入真实工具或开放给其他用户。
我的最终选择是：日常任务优先官方 4-bit + DFlash2；代码生成和长输出切到 oQ4e + MTP；需要最少依赖时使用官方 4-bit；Uncensored 只在隔离环境中测试。下一步如果要做真正的四组总排名，还需要让 MTP 跑完同一套短提示与 GSM8K 脚本，再统一采样参数、输出长度和首 token 统计方式。
