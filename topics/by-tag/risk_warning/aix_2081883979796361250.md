## 原文

@MF_Camillus Check out $MU’s white paper about how DRAM increases performance. Here’s an ai summmary:

This slide is one of the better pieces of evidence supporting the idea that AI infrastructure is increasingly becoming memory constrained, not just compute constrained. It’s also bullish for Micron because it demonstrates why higher DRAM capacity can produce disproportionately better performance.

Here’s what’s happening.

The test

Micron compared two servers that were essentially identical:

* Same CPUs
* Same number of cores
* Same cache hierarchy
* Same software
* Same Spark workload

The only meaningful difference was memory capacity.

SKU1 had 2x the DRAM of SKU2.

That isolates memory as the performance variable.

The results

The larger memory system produced:

* 2.82x higher throughput under a normal workload
* 3.45x higher throughput under a 3x heavier workload
* Similar reductions in execution time

Those are huge gains considering no CPU was upgraded.

Why does this happen?

The key is this sentence:

“Shuffle data exceeds available DRAM and spills to SSD.”

In large AI and analytics workloads, data must constantly move between processing stages.

If there isn’t enough DRAM:

1. memory fills up
2. data is written (“spilled”) to SSD
3. SSD is thousands of times slower than DRAM
4. the CPUs and GPUs sit idle waiting for data

Adding memory keeps the working dataset entirely in RAM.

The most important chart

The eye catching number is:

38.75× slowdown in Stage 2

That doesn’t mean the entire application is 39 times slower.

It means one stage becomes catastrophically slow once memory runs out.

This illustrates a common systems engineering principle:

One bottleneck dominates the entire workload.

Removing that bottleneck dramatically improves overall performance.

The second bottleneck

Micron also points out another issue.

With too little memory, the operating system cannot keep enough pages cached.

Instead of reading data from DRAM, it repeatedly rereads SSD.

That explains the:

* 5.96× slowdown
* 4.25× slowdown
* 3.21× slowdown

during the heavier workload.

Again, compute isn’t the problem.

Memory capacity is.

⸻

1. AI scaling is becoming a memory problem

Everyone focuses on GPUs.

This suggests the next constraint increasingly becomes:

* HBM
* DDR5
* CXL memory expansion
* Memory bandwidth
* Total server memory capacity

That is constructive for companies like:

* Micron
* SK hynix
* Samsung

and indirectly for:

* NVIDIA
* AMD

because larger memory pools allow their accelerators to stay fully utilized.

2. More memory means better ROI on expensive GPUs

A $40,000 to $70,000 GPU is a poor investment if it spends time waiting on storage.

Increasing DRAM can unlock significantly more useful work from the same GPU investment.

This is why hyperscalers continue to spend aggressively on memory alongside compute.

3. It reinforces the “physical infrastructure” thesis

This is another example of AI shifting from “buy more chips” to optimizing the entire stack:

* power
* cooling
* networking
* memory
* storage
* data center design

Exactly the broader capital spending cycle your macro framework anticipates.

One caveat

This is a Micron white paper, so it is marketing material as well as technical documentation.

The benchmark appears credible because it isolates a single variable, but the exact magnitude of the gains may not generalize to every workload. Spark jobs that perform large shuffle operations are especially sensitive to memory capacity.

Investment takeaway

The broader conclusion is more important than the exact percentages:

* AI performance is increasingly constrained by memory, not just compute.
* Additional DRAM capacity can produce nonlinear performance gains by eliminating disk I/O bottlenecks.
* As AI models and context windows continue to grow, memory content per server is likely to keep increasing, supporting sustained demand for high bandwidth memory (HBM) and server DRAM.
