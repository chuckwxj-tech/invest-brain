🔻 Linux 7.2 Release Notes 

Linux 7.2 is a major feature release focused on scheduler efficiency, GPU enablement, memory performance and storage.

Biggest highlights: cache-aware CPU scheduling, a fairer DRM GPU scheduler, AMD HDMI 2.1 FRL + DCN 4.2.1 support, Intel Xe3p/CRI enablement, NVIDIA Hopper/Blackwell work, major Btrfs performance gains, improved memory reclaim, USB4STREAM and dm-inlinecrypt.

🖥️ Graphics / GPU
• All vendors: New fair(er) DRM GPU scheduler → improves fairness and latency for interactive GPU workloads running alongside heavy GPU jobs

• AMD: Initial HDMI 2.1 FRL support → groundwork for native high-bandwidth HDMI 2.1 operation on supported AMD GPUs

• AMD: Initial DCN 4.2.1 display-engine support → enables newer AMD display hardware generations

• AMD: Adds GC 11.5.6, SDMA 6.4.0 and additional new GPU IP blocks → expands support for upcoming/newer AMD GPU hardware

• AMD: Enables the DC power module → expands display-side power-management support

• AMD: Finishes multi-SDMA-queue support for TTM operations → allows memory-management operations to use multiple DMA queues

• AMD: Adds Auxless ALPM support → extends DisplayPort link power-saving capabilities

• AMD: Adds PTL control module parameter and additional KFD/profiler infrastructure

• Intel: Xe gains initial CRI platform support

• Intel: Xe3p gets TileY 2x2 walk-pattern GT tuning

• Intel: Adds Xe system-controller support for Xe3p discrete GPUs

• Intel: Xe PF fair-scheduling auto-provisioning added for SR-IOV / virtualization scenarios

• Intel: i915 gains pipe background-color support

• NVIDIA: nouveau fixes multiple GA100 / Ampere issues

• NVIDIA: nouveau can now expose VBIOS through debugfs on GSP-RM systems

• NVIDIA: nova-core gains firmware support for Hopper and Blackwell GPUs

• NVIDIA: nova-core adds GA100 support

• NVIDIA: nova-core now runs proper firmware unload sequence when unbinding

• Qualcomm: Adds Adreno 810 GPU support

• Qualcomm: Adds PERFCNTR_CONFIG ioctl for MSM GPU performance-counter configuration

• ARM Mali / Panthor: Adds GEM shrinker → GPU memory can participate more effectively in system memory reclaim

• Raspberry Pi / Broadcom: V3D gains GPU power-management support

⚙️ CPU / Scheduler / Power
• All vendors: New cache-aware scheduler → tries to keep tasks sharing data inside the same Last Level Cache domain, reducing cache bouncing and misses

• All vendors: Scheduler topology work improves placement of related threads across cores / LLC domains

• All vendors: sched_ext gains topology-ordered CPU IDs and infrastructure for future sub-schedulers

• All vendors: Fair scheduler gains better SMT awareness for asymmetric CPU-capacity systems

• Intel: Adds CPU model ID for rugged Panther Lake variants

• Intel: intel_pstate now derives non-turbo capacity from HWP_GUARANTEED_PERF → improves scheduler capacity accounting on HWP systems

• Intel: Runtime TDX module update support added → TDX modules can be replaced without requiring a normal platform firmware cycle

• AMD: x86 CPU handling now explicitly carves out the Zen 5 model range

• AMD: Adds support for Family 1Ah Model 80h SoCs in AMD PMC

• AMD: AMD PMC gets additional s2idle handling for affected devices

• AMD: KVM mediated PMU passthrough gains Host-Only / Guest-Only performance-counter event-select support

• AMD: KVM can virtualize the “disable CPUID in usermode” feature

• AMD: Legacy AMD Elan cpufreq support removed

• Qualcomm: Adds cpufreq scaling support for Shikra SoCs

• All vendors / ACPI: CPPC v4 support added, matching ACPI 6.6

🧠 Memory / Performance
• All vendors: MGLRU reclaim loop and dirty-writeback handling reworked → up to ~30% improvement reported in some MongoDB/YCSB workloads and fewer unexpected OOMs

• All vendors: Swap-table phase IV → lower metadata overhead and slightly better swap performance

• All vendors: A 1 TB swap device can save roughly 512 MB of static metadata compared with the previous design

• All vendors: iomap avoids a pointless memset after iteration → around 5% higher IOPS reported for 4K random NVMe reads on ext4/XFS via io_uring

• All vendors: Pipe allocation moved outside pipe->mutex → significantly lower contention and higher throughput under multi-reader/writer and memory-pressure workloads

💾 Storage / Filesystems
• Btrfs: Large folios enabled by default

• Btrfs: Experimental huge-folio support up to 2 MiB on 4K-page systems

• Btrfs: New GET_CSUMS ioctl allows userspace to retrieve raw file checksums

• Btrfs: Sequential-write tuning reports around 15% improvement

• Btrfs: Direct-I/O writes no longer forced to serialize → reported ~59% DIO throughput improvement in affected workloads

• Btrfs: Better compressed readahead for block-size < page-size and large-folio configurations

• Btrfs: Faster extent-map shrinking and fragmented-hole handling

• Device Mapper: New dm-inlinecrypt target → enables inline block-device encryption and can serve as a practical alternative to dm-crypt on supported hardware

• VFS: Adds OPENAT2_REGULAR → callers can require that a path resolves only to a regular file

• VFS: Adds O_EMPTYPATH → permits reopening the object behind an existing file descriptor with an empty pathname

🔌 USB / Connectivity
• USB4 / Thunderbolt: New USB4STREAM support → raw data streams can be sent directly between hosts over USB4

• USB4STREAM exposes /dev/tbstreamX devices usable with normal read/write operations

• USB4STREAM can coexist with Thunderbolt networking and supports multiple streams

• USB-C / UCSI: Adds SET_PDOS command support

• AMD: Promontory 21 XHCI gains temperature-sensor support

🌐 Networking
• TCP/network stack gets broad performance and correctness work across drivers and protocol paths

• io_uring networking gains registered-buffer support for normal send/recv operations

• io_uring can now filter IORING_OP_CONNECT

• Wi-Fi: ath12k gains further MLO peer handling improvements

• Wi-Fi: mt76 / MediaTek receives multiple robustness and capability fixes

• Bluetooth: extensive ISO connection lifetime/refcounting cleanup → fixes several leaks, deadlocks and use-after-free paths

🔐 Security / Hardening
• BPF: Adds cBPF JIT spray hardening

• x86: Safe-RET handling strengthened against interrupt injection

• x86: IBPB flush added when allocating BPF JIT memory

• Kernel-wide: strncpy() removed from the kernel

• openat2: OPENAT2_REGULAR helps services reject FIFOs/device nodes when they expect normal files

• io_uring and networking receive multiple overflow, bounds and lifetime hardening fixes

🔥 TL;DR
• All GPUs: New fair(er) DRM scheduler → better latency under competing GPU loads
• AMD: HDMI 2.1 FRL + DCN 4.2.1 + new GC/SDMA IP support
• Intel: Xe CRI/Xe3p enablement + Xe3p dGPU system controller
• NVIDIA: Hopper/Blackwell firmware support + GA100/nouveau work
• Qualcomm: Adreno 810 support
• CPU: New cache-aware scheduler reduces LLC cache bouncing
• Intel: Panther Lake ID + TDX runtime module updates
• AMD: Zen 5 model handling + newer PMC/KVM support
• Memory: MGLRU improvements + dramatically leaner swap metadata
• Btrfs: large folios default + major sequential/DIO performance gains
• USB4: New USB4STREAM host-to-host raw streaming
• Storage: New dm-inlinecrypt target
