$NVDA $AMD $INTC $GOOGL HOT CHIPS 2026 DAY 1: TECHNICAL HIGHLIGHTS

THE FUTURE IBM Z AND LINUXONE PROCESSOR AND AI INFERENCE ACCELERATION CHIPSET — CHRISTIAN ZOELLIN — IBM

IBM disclosed a 2 nm, 11-core, 2-way-SMT enterprise processor in which each hardware thread can independently execute either z/Architecture or AArch64 and switch between the 2 modes within nanoseconds. The design uses 1 shared physical core rather than separate Z and Arm core clusters.
The processor operates at a stated base frequency of 5.7+ GHz and includes 36 MB of private L2 cache per core, approximately 432 MB of virtual L3 capacity on chip, and approximately 3.5 GB of virtual L4 capacity across a system.
AArch64 v9.3, SVE, SVE2, and Arm SystemReady compatibility are implemented directly in the mainframe core. IBM added 2,792 AArch64 instructions and 239 AArch64 system registers while preserving the existing high-frequency pipeline and mainframe execution infrastructure.
The implementation reuses the existing branch predictors, TLBs, caches, register-renaming structures, arithmetic datapaths, load-store machinery, and precise-recovery mechanisms wherever the 2 ISAs have compatible semantics. New hardware was required for AArch64 table walking, SVE control, FP16, BF16, cryptography, architectural exceptions, and little-endian execution over a largely big-endian internal design.
Mixed s390x and Arm64 virtual machines can operate under the same KVM and OpenShift environment. A physical thread changes execution mode when the hypervisor dispatches the corresponding virtual CPU, allowing modern Arm software to run adjacent to mission-critical systems of record.
Arm workloads inherit IBM Z features including checkpoint recovery, spare-core migration, nested virtualization, concurrent repair, compression, cryptography, AI acceleration, I/O acceleration, and mainframe-class fault detection.
The 2nd-generation PCIe AI accelerator contains 16 active AI cores and 1 redundant core, supports FP4 and MXFP4, provides up to 4x the prior generation’s FP8 arithmetic capability, and incorporates 96 GB of HBM3E with more than 4 TB/s of bandwidth.
The accelerator’s approximately 20x memory-bandwidth increase reflects the transition from predictive enterprise inference toward generative and agentic workloads, where model weights, KV caches, activations, and intermediate state can dominate arithmetic demand.
The accelerator connects through PCIe Gen6 x16 and supports peer-to-peer connectivity, secure boot, on-chip cryptography, dynamic power management, work queues, redundant compute capacity, and integration with mainframe confidential-computing and serviceability frameworks.

INTEL CORE SERIES 3, CODENAME WILDCAT LAKE — LANCE HACKING — INTEL

Wildcat Lake is a value-optimized derivative of Core Ultra Series 3, codename Panther Lake, designed to retain current-generation CPU performance and platform functionality while removing silicon and package content that provides limited value in mainstream notebooks and edge systems.
Intel replaced Panther Lake’s Foveros package and passive base die with a 2-die organic multi-chip package containing an Intel 18A compute die and a TSMC N6 platform-I/O die connected through UCIe.
The package shrinks from approximately 50 mm × 25 mm × 1.5 mm to approximately 35 mm × 25 mm × 1.23 mm. Eliminating the base die reduces package cost, assembly complexity, and yield exposure.
Compute was aggressively right-sized: P-cores decline from 4 to 2, LLC from 12 MB to 6 MB, integrated Xe cores from 4 to 2, NPU engines from 3 to 1, NPU performance from 53 TOPS to 17 TOPS, LPDDR5 interface width from 128 bits to 64 bits, and system cache from 4 MB to 2 MB.
Intel retained XMX acceleration and cited unchanged single-thread CPU performance while removing ray tracing, the IPU, professional-media features, camera PHYs, 1 display pipe, and selected high-end I/O capabilities.
Combined compute-and-GPU die area declines approximately 38%, while the platform-I/O die declines approximately 15%. The design demonstrates that mainstream product economics increasingly depend on selective IP removal rather than reuse of an older CPU architecture.
The organic UCIe implementation uses a coarser approximately 110 μm interconnect pitch than Foveros and requires materially more controller and PHY area. UCIe therefore increases architectural reuse but is not inherently area-free or cost-free.
The die-to-die link uses 16-wide channels at 8 GT/s and provides approximately 12 GB/s of cited main-link bandwidth. Display traffic is buffered to increase low-power-link residency, and hundreds of sideband signals are packetized across UCIe.
Intel did not implement full retry or forward-error correction on the UCIe link, relying instead on physical validation and lower-frequency fallback for marginal links.
Approximately 29% of the Intel 18A compute die can be recovered through SKU harvesting, improving economic utilization of partially defective dies.
Intel cited up to 40 platform TOPS, up to 2.7x higher AI performance, up to 2.1x higher creation and productivity performance, and up to 64% lower processor power versus Core 7 150U under Intel-selected configurations.

NVIDIA VERA CPU — JONATHON EVANS AND POLYCHRONIS XEKALAKIS — NVIDIA

Vera is a custom NVIDIA CPU designed specifically for agentic workloads, including tool execution, browser and code sandboxes, data processing, security, orchestration, retrieval, and CPU phases that can leave high-value GPUs idle.
The processor contains 88 NVIDIA-designed Olympus cores and supports 176 hardware threads through spatial multithreading. Each core has 2 MB of private L2 cache, while the package provides 164 MB of distributed system-level cache.
The package contains 6 dies: 1 monolithic 88-core compute die, 4 LPDDR5X memory-controller dies, and 1 system-and-I/O die. NVIDIA deliberately avoided on-package compute sub-NUMA domains to preserve cross-core bandwidth and simplify software placement.
Vera supports up to 1.5 TB of ECC-protected LPDDR5X and up to 1.2 TB/s of raw memory bandwidth through 32 × 32-bit channels operating at 9,600 MT/s.
NVIDIA’s 2nd-generation Scalable Coherent Fabric provides approximately 3.4 TB/s of bisection bandwidth, 164 MB of distributed cache, and up to 100 GB/s of cited streaming-write bandwidth per core.
Host and accelerator connectivity includes approximately 1.8 TB/s of NVLink-C2C bandwidth, up to 96 PCIe 6.4 lanes, CXL 3.1 Type 3 memory expansion and pooling, and configurable package power from 250 W to 450 W.
The Olympus core uses a 10-wide decode architecture, a more than 1,000-instruction out-of-order window, neural-assisted and TAGE-based branch prediction, support for 2 taken branches per cycle, 128 bytes per cycle of instruction fetch, and aggressive graph and pointer-chasing prefetch.
Execution resources include 6 integer ALUs, up to 4 loads per cycle, 2 stores per cycle, 6 vector operations per cycle, a 96 KB data cache, memory renaming, and value prediction. The design prioritizes high single-thread performance without reverting to a low-core-count frequency-optimized CPU.
Spatial multithreading statically partitions many branch-prediction, scheduling, register, and execution resources between 2 threads. This is intended to provide more deterministic latency and stronger isolation than conventional dynamic SMT, at the cost of potentially stranding resources when 1 thread is underutilized.
Vera and Rubin implement encryption and trusted execution across CPU memory, GPU memory, PCIe, NVLink-C2C, and rack-scale accelerator communication.
NVIDIA cited up to 1.8x gains on selected agentic proxies, up to 1.7x on selected EDA workloads, and up to 1.5x on selected data-processing workloads. The presentation combined hardware projections, early silicon measurements, and software changes rather than providing a uniform independent benchmark suite.

NEXT-GENERATION ARM-BASED CPU FUJITSU-MONAKA FOR GREEN AI DATA CENTER — RYOHEI OKAZAKI — FUJITSU

MONAKA is a 144-core Arm v9.3-A processor designed for AI orchestration, HPC, sovereign infrastructure, high-precision computing, and power-constrained data centers. A 2-socket node supports 288 cores.
Each core contains 2 256-bit SVE2 execution units and 2 256-bit load-store units, with support for FP8 and INT8 matrix operations in addition to conventional HPC datatypes.
The processor provides 12 DDR5 channels at 8,000+ MT/s, 96 PCIe 6.0 lanes, CXL 3.0, confidential computing, and both air-cooled and liquid-cooled operating points.
MONAKA uses a 3D multi-die architecture in which TSMC N2P core dies are placed above a TSMC N5 SRAM die containing the last-level cache. N5 I/O dies connect through a silicon interposer.
Less than 30% of total silicon area uses N2P. SRAM, analog power circuitry, I/O, and other structures with weak leading-edge scaling are moved to N5 to reduce cost and shorten the development cycle.
Face-to-face hybrid bonding creates a short, high-density connection between the core dies and SRAM die. The hottest core dies are placed closest to the cooling surface to minimize thermal resistance.
Local LDOs are placed on the N5 SRAM die beneath high-power execution blocks. Power is delivered through the package, interposer, SRAM-die TSVs, LDOs, and hybrid bonds to enable per-core voltage and frequency management.
Fujitsu stated that the cores can operate at approximately 30% below nominal voltage. Under the simplified dynamic-power relationship P ∝ CV²f, this corresponds to approximately 50% lower dynamic power, although complete processor power does not scale uniformly with voltage.
Proprietary power optimizations include an FPR cache that avoids repeated main-register-file reads, recognition of common predicate-register patterns, suppression of unnecessary upper-bit writes, and custom SRAM validated for ultra-low-voltage operation.
Mainframe-class RAS includes ECC or duplication in L1 and L2, parity protection in execution structures and registers, and hardware instruction retry for transient faults.
Flexible NUMA modes include 8 × 18-core domains, 4 × 36-core domains, and 1 × 144-core domain, allowing software to trade local latency against a simpler unified memory model.
Air-cooled and liquid-cooled SKUs were presented at approximately 350 W and 500 W, with approximately 2.1 GHz and 2.9 GHz base frequencies. Evaluation samples were stated to be shipping, with product shipments planned for 2027.

ARM AGI CPU: A DISAGGREGATED, CHIPLET-BASED SERVER SOC FOR SCALABLE COHERENCY AND MEMORY BANDWIDTH IN THE TERABYTE/S ERA — SAURABH PRADHAN AND DEEPAK GOEL — ARM

Arm presented AGI CPU as a transition from licensing cores and compute subsystems toward delivering production server silicon.
The processor uses 2 homogeneous TSMC N3P compute chiplets. Each chiplet contains 70 physical Neoverse V3 cores and more than 50 billion transistors, while the complete socket supports up to 136 active cores, leaving 4 physical cores available for yield harvesting.
Each Neoverse V3 core includes 64 KB instruction and data caches, 2 MB of private L2, a 10-wide front end, a 384+ entry out-of-order window, 10-wide dispatch, 8-wide retirement, 8 integer ALUs, 3 branch units, and 2 128-bit vector datapaths.
The socket includes 128 MB of distributed system-level cache and an 8-row × 9-column CMN-S3 coherent mesh with snoop filtering, hierarchical caching, CHI-F coherency, and RAS.
The memory subsystem contains 12 DDR5 controllers, supports up to DDR5-8800 subject to commercial qualification, and targets approximately 845 GB/s of aggregate bandwidth, approximately 6 GB/s per active core, and up to 6 TB of capacity.
The 2 chiplets communicate through an approximately 1 TB/s-per-direction UCIe connection. The high die-to-die bandwidth is required to make unified NUMA operation viable without turning remote-chiplet memory into a severe bottleneck.
NUMA1, NUMA2, and NUMA4 configurations allow software to choose among uniform addressing, chiplet-local memory, and smaller latency-optimized regions. Arm cited sub-100 ns memory latency in NUMA2.
I/O includes 96 PCIe Gen6 lanes, CXL 3.0 Type 3 memory expansion, coherent accelerator attachment, and 2-socket SMP support.
Hierarchical management uses a system control processor, local control processors, a management control processor, and a runtime security engine for power management, board management, root of trust, and secure initialization.
The architecture targets a 300 W socket, with approximately 2.8 GHz typical operation, 3.5 GHz nominal operation, and up to 3.7 GHz boost under selected conditions.
The use of 2 homogeneous chiplets is deliberately less aggressive than a multi-node compute, cache, memory, and I/O disaggregation. The design prioritizes execution speed, validation simplicity, and predictable NUMA behavior over maximum chiplet specialization.

DIAMOND RAPIDS: NEXT GENERATION INTEL XEON CPU — AKHILESH KUMAR AND KRISHNAKANTH SISTLA — INTEL

Diamond Rapids introduces a fan-out fabric architecture composed of 4 scalable compute building blocks connected to 2 centralized fabric hubs.
The package contains up to 16 Intel 18A-P core chiplets stacked through hybrid bonding on 4 Intel 3 base tiles. The base tiles contain shared LLC, caching agents, snoop filters, and die-to-die connectivity.
Each core chiplet supports up to 16 P-cores. The complete socket scales to as many as 256 P-cores and approximately 1.28 GB of aggregate LLC.
A dense 3D crossbar connects the core chiplets to shared LLC on the underlying base tile. This separates frequency-sensitive compute from large cache and coherence structures that scale differently with process technology.
The fabric hubs centralize DDR controllers, memory encryption, home agents, snoop filters, I/O, accelerators, and flexible interconnect functions. Intel prioritizes relatively uniform memory access across compute building blocks rather than exposing strongly asymmetric local and remote memory.
The memory subsystem supports 16 DDR channels at up to DDR5-8000 or MRDIMM rates up to 12,800 MT/s, providing approximately 1.6 TB/s of cited aggregate bandwidth.
I/O includes 128 PCIe Gen6 lanes plus 8 PCIe Gen4 lanes. The platform also supports QAT, DSA, IAA, AMX, AVX10.2, APX, TDX, TDX Connect, SGX, and memory-encryption features.
APX expands the architectural general-purpose-register file to 32 registers and adds 3-operand forms, conditional operations, and flag-suppression capabilities intended to improve compiler scheduling and code density.
Shared and read-mostly data can be replicated across compute-building-block caches, while distributed snoop filters reduce unnecessary coherence traffic across the package.
Hierarchical power management controls individual cores, compute building blocks, fabric, memory, and I/O. Priority-core turbo can direct additional frequency and power toward CPU threads servicing latency-sensitive GPU-host tasks.
Intel stated that 18A provides approximately 15% better performance per watt than Intel 3, with 18A-P providing approximately 9% additional performance. These were process-level claims rather than complete Diamond Rapids benchmark results.
Final operating frequency, socket power, launch timing, package yield, and workload performance were not disclosed. The design’s technical potential therefore remains highly dependent on 18A-P yield, hybrid-bonding yield, thermal behavior, and final system power.
