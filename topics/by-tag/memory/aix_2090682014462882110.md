## 原文

「推論データの置き場所」特集②

CXLは、HBMの代わりではない。

正しくは、
HBMからあふれるKV Cacheを受け止める
「中間メモリ層」の有力候補。

AI推論では、
・Contextの長文化
・同時接続数の増加
・AIエージェントの長時間稼働
によって、KV Cacheが猛烈に膨らむ。

しかし、すべてを高速だけど容量の限られるHBMに置き続けるのは難しい。
そこで、

最もHotなKV Cache
→ HBM

HBMから退避するKV Cache
→ CPU DRAM / CXL Memory

再利用・永続化するCache
→ NVMe SSD

RAGの参照データや生成物
→ Object Storage / HDD
という階層化が必要になる。

CXLは、HBMとSSDの間に大容量DRAMを追加・共有しやすくする技術。

そして「CXL関連銘柄」も、役割によって全然違う。

【DRAM / CXL Memory Module】
→ $MU

【CXL Memory Controller】
→ $ALAB Leo
→ $MRVL Structera X
→ $MCHP SMC

【CXL Switch / Memory Pooling】
→ $MRVL Structera S

【KV Cache Server / System】
→ $PENG MemoryAI

【CXL Retimer / 接続延伸】
→ $ALAB Aries
→ $CRDO Toucan

【CXL Controller / PHY IP】
→ $SNPS $CDNS $RMBS

つまり、

CXL＝ $ALAB
だけではない。

DRAMを供給する会社
接続を制御する会社
ラック内で共有する会社
KV Cache Serverとして組み上げる会社
チップ設計用IPを提供する会社
それぞれ取り分が違う。

ただし、
「CXL製品を持っている」
と
「CXLが業績を動かす」
は別の話。

ここから確認したいのは、

① 本番環境への採用件数
② 1台・1ラック当たりの搭載金額
③ KV Cache Offloadの実性能
④ CXL売上が会社全体に占める比率
⑤ Memory Poolingが量産段階に入る時期

CXLの勝者を探すなら、製品の有無ではなく、

「推論Memory Wallの解消で、誰の売上が一番増えるのか？」まで見たい。

次回は、中心候補の
$ALAB $MRVL $MU $PENG
を比較します🔍
