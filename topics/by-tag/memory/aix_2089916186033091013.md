## 原文

I don’t buy Cathie Wood’s memory argument.
Her logic: HBM prices triple or quadruple, engineers redesign around it, use less. Cerebras and Groq are her proof points. Conclusion: the memory boom is cyclical, not structural.
Here’s where I get off the train. “Less HBM” doesn’t mean “less memory.” Those are different claims wearing the same sentence.
AI systems run on a hierarchy, not a single memory type. SRAM is fast, expensive, and capacity-constrained. HBM offers huge bandwidth but is also expensive. DRAM gives you cheap capacity. CXL and NAND stretch the hierarchy further down. If HBM gets too expensive, the system doesn’t just shrink its memory footprint. It reorganizes. Latency-sensitive data moves into SRAM, everything else gets pushed down into DRAM, CXL, NAND.
Inference makes this worse, not better. It’s not just weights anymore. It’s context windows and KV cache, both growing. More agentic workloads, longer context, more persistent state. The raw amount of data that needs storing and moving can keep climbing even while architecture gets more efficient per unit of compute.
Sure, better KV cache compression, bigger on-chip SRAM, and smarter inference architectures could cut external memory needs a lot. That’s the real counterargument.
So the question isn’t cyclical vs. structural. It’s whether memory efficiency improves faster than workloads grow.
I don’t think it does.
Cerebras and Groq might be right that GPU+HBM isn’t the final architecture. Fine, I’ll take that bet too. But that doesn’t make memory less important. It just changes which layer wins.
The bottleneck in AI stops being pure compute and starts being how fast and how cheap you can move an exploding pile of data around. That’s the bull case for memory.
