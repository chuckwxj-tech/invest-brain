This is why I love X. S/o @damnang2 for the incremental roadmap color from his meeting with a Samsung VP

Update on zHBM: 

When Samsung unveiled zHBM at FMS a few weeks ago, I admittedly wondered, given the performance targets [~8× HBM5 performance, >10× memory density, ~3× energy efficiency, >50% lower thermal resistance], whether zHBM and the conventional HBM roadmap would coexist in the future. But it increasingly looks like they will continue developing the conventional HBM line alongside zHBM.

You'll have conventional HBM (HBM4 -> HBM4E -> HBM5 -> ...) as the broadly standardized interface/architecture that will be manufactured at large volumes, with customers designing many different accelerators around it. (note: it can still become highly customized through the base die - SK already described cHBM this way)

And then you’ll have zHBM, where memory is stacked directly onto the xPU with customer-specific IP between memory and compute. Because here the entire compute-memory stack is co-optimized, you'll see enormous bandwidth density/efficiency, but it will make the components far more tightly coupled. 

Not every future workload will need maximum bandwidth density enough to justify that tighter coupling and full 3D integration. Some will care more about capacity, cost, memory pooling/sharing across accelerators than maximizing bandwidth density/xPU.

Other helpful color:

-> MicroLED: Samsung maybe elevating microLED optical I/O to a roadmap item? Would be joining SK hynix in doing so. Helpful validation that microLED is becoming a credible path through the interconnect wall.

-> CPO: Timing-wise, Samsung still sees broader compute-side CPO (and likely optical memory interfaces) adoption as a 2030+ story

-> NAND: Samsung appears to be prioritizing zNAND for on-device/edge AI over HBF for data centers vs SK hynix/Sandisk's HBF push (potential start of NAND roadmap/product divergence here?)

-> CXL: Further validation of the tiered-memory architecture, with CMM-D complementing custom HBM. Good confirmation that we'll see system-level gains without every incremental GB needing to be expensive HBM.
