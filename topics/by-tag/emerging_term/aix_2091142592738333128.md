## 原文

「推論データの置き場所」特集⑥

CXL最大のライバルは、SOCAMMなのか？

結論から言うと、
SOCAMMはCXLの完全な代替ではない。

ただし、
CXL Memoryが必要になるタイミングを遅らせる、強力な競合
にはなり得ると思う。

SOCAMMは、低消費電力なLPDDRをサーバー向けの着脱可能なメモリモジュールにしたもの。

NVIDIA Vera CPUでは、

・最大1.5TBのLPDDR5X
・最大1.2TB/sの帯域
・従来型DDR構成より低い消費電力

を狙っている。

CPU直結のローカルメモリが、
大容量・高帯域・低消費電力
になれば、HBMから退避したKV CacheをCPU側に置ける範囲も広がる。

すると当然、
「わざわざCXL ControllerやCXL Switchを追加する必要があるのか？」
という疑問が出てくる。

ただし、SOCAMMとCXLでは役割が違う。

SOCAMM
→ 各サーバー内のローカルメモリを強化する

CXL
→ サーバーの外側へメモリを拡張し、共有・プールする

SOCAMMは「自分のメモリを大きくする」技術。

CXLは「メモリをサーバーから切り離し、必要な場所へ割り当てる」技術。

だから本当の論点は、

SOCAMM vs CXL

ではない。

HBM／SOCAMMと共有Flashの間に、
CXL Memoryという中間層が本当に必要になるのか？

だと思う。

CXLの弱気シナリオは、

HBM
↓
SOCAMM / CPU Memory
↓
CMXなどの共有NVMe Flash
↓
Object Storage

という構成だけで、推論データの階層化が成立すること。

実際、NVIDIAが示しているVera Rubinの構成では、

・CPU側の大容量メモリにSOCAMM
・Pod全体のKV Cache置き場にCMX
・CMXはEthernet接続の共有Flash層

を採用している。

つまり、

高速なローカルメモリ
と
安価で大容量な共有Flash

で上下から挟まれた場合、CXL Memoryの必要性が薄くなる可能性がある。

逆にCXLが勝つ条件は、

① 1台のSOCAMM容量では足りない
② サーバーごとのメモリ使用量に偏りがある
③ Memory Poolingで利用率を改善できる
④ CXLによる遅延やコストを上回るTCO効果がある
⑤ 複数ベンダー間で共有できるオープン性が求められる

こと。

銘柄で整理すると、

SOCAMMが主役
→ $MU

CXL Memoryが主役
→ $ALAB $MRVL $PENG $MU

共有Context Storageが主役
→ $P $NTAP $DELL
→ NAND / SSDでは$SNDK $MU

このテーマ内では、$MUはかなり面白い。
SOCAMMが勝ってもLPDRAMを売れる。
CXLが勝ってもDRAMやCXL Memory Moduleを売れる。

どの経路でも、

推論に必要なメモリ容量そのものが増える
ことを取りにいけるから。

一方、$ALABや$MRVLを見るなら、
「推論Memory Wallが来るか？」
だけでは不十分。

その解決策として、本当にCXLが選ばれるか？
まで検証しないといけない。

私の現時点の結論は、
CXLの最大の敵はSOCAMM単体ではない。

SOCAMMと共有Flashによって、
CXLの中間メモリ層を飛ばされること
が最大の弱気シナリオだと思う。

次回は、CXLを飛び越えてKV Cacheを受け止める、
NVIDIA CMXとAI Storage関連銘柄
を掘ります🔍
